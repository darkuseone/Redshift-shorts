# Клипы аватара — вход двухфазного конвейера

Ключа HeyGen в секретах репозитория нет, а цифровой двойник ведущего занимает
35–60 % хронометража (§3.5). Разрыв закрывается в два захода.

## Фаза 1 — Actions

Прогон доходит до P6, режет `voice_final.wav` на куски по границам фраз и
останавливается с кодом `AVATAR_CLIPS_NOT_PREPARED`. В артефакте
`avatar-request` лежат:

- `work/<video_id>/avatar_request.json` — что именно нужно сгенерировать;
- `work/<video_id>/avatar/seg_NN.wav` — куски речи, под которые строится липсинк.

## Фаза 2 — снаружи

Клипы генерируются по этим кускам (MCP-коннектор HeyGen в чате Claude) и
кладутся сюда:

```
assets/avatar_clips/<video_id>/seg_00.mp4
assets/avatar_clips/<video_id>/seg_01.mp4
...
```

Забирает их `tools/fetch_avatar_clips.py`: он качает клипы по ссылкам и сверяет
длительность каждого с куском речи тем же допуском, что и провайдер.

Требования, которые проверяет провайдер:

- **длительность** совпадает с куском речи с точностью 0.2 сек — иначе липсинк
  уедет, и это видно на первом же слове;
- **`.mov` или `.webm`** несут альфу, `.mp4` — нет. На практике альфы нет ни в
  одном: фотоаватар отдаёт непрозрачный кадр в обоих форматах (проверено —
  webm приходит `yuv420p` с альфой 255 на всём кадре, да ещё и высотой 1936
  вместо 1920). Поэтому рабочий формат здесь `.mp4`, аватар идёт непрозрачным
  планом, а `heygen.prepared_chroma` выключен: заказанный фон фотоаватар тоже
  игнорирует, снимать нечего.

## Фаза 3 — Actions

Прогон возобновляется с `--from P6` и находит клипы готовыми.

Клипы **хранятся в git** — иначе фазе 3 их взять неоткуда. Артефакт workflow
работает только в одну сторону, фаза 1 → фаза 2: его создаёт сам прогон, и шага,
который скачал бы клипы обратно на раннер, в workflow нет. На раннер они
попадают вместе с `checkout`. Цена — около 8 МБ на ролик; `.gitignore` пропускает
именно `seg_*` и по-прежнему держит снаружи всё промежуточное.
