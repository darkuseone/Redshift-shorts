# Клипы аватара — вход двухфазного конвейера

Ключа HeyGen в секретах репозитория нет, а цифровой двойник ведущего занимает
35–60 % хронометража (§3.5). Разрыв закрывается в два захода.

## Фаза 1 — Actions

Прогон доходит до P6, режет `voice_final.wav` на куски по границам фраз и
останавливается с кодом `AVATAR_CLIPS_NOT_PREPARED`. В артефакте
`avatar-request` лежат:

- `work/<video_id>/avatar_request.json` — что именно нужно сгенерировать;
- `work/<video_id>/avatar/seg_NN.wav` — куски речи, под которые строится липсинк.

## Фаза 2 — снаружи

Клипы генерируются по этим кускам (MCP-коннектор HeyGen в чате Claude) и
кладутся сюда:

```
assets/avatar_clips/<video_id>/seg_00.mov
assets/avatar_clips/<video_id>/seg_01.mov
...
```

Требования, которые проверяет провайдер:

- **длительность** совпадает с куском речи с точностью 0.2 сек — иначе липсинк
  уедет, и это видно на первом же слове;
- **`.mov` или `.webm`** несут альфу и позволяют положить аватара на фон,
  собранный в браузере; `.mp4` принимается, но фон останется таким, как его
  отдал HeyGen.

## Фаза 3 — Actions

Прогон возобновляется с `--from P6` и находит клипы готовыми.

Сами файлы в git не хранятся: они тяжёлые, а `.gitignore` пропускает только
этот README. Для передачи между фазами используется артефакт workflow.
