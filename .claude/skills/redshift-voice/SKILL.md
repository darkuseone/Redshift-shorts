# redshift-voice

## Запас длины (§4.2.4) — не украшение

Озвучка заказывается на **+18…25 %** длиннее целевой. Смысл: после срезки пауз
ролик не должен провалиться ниже 35 сек. Если провалился — система возвращает
`SCRIPT_TOO_SHORT` **с расчётом недостающих секунд и слов**, а не выдаёт
короткий ролик.

P2 контролирует факт: если длина отклонилась больше чем на 12 %, делается одна
корректирующая переозвучка с пересчитанной скоростью. Больше одной — запрещено,
это удвоение расхода.

## Озвучка идёт поблочно

Так границы блоков известны точно, можно переозвучить один блок, и P6 получает
готовые интервалы фраз для посегментной генерации аватара.

## Ударения и произношение (§4.2.5, R-5)

Словарь — `config/pronunciation.json`:

```json
{"words": {"кубит": {"stress": 3, "confirmed": true}},
 "abbreviations": {"NASA": "НАСА"},
 "units": {"%": "процентов"}}
```

* `stress` — индекс ударной гласной (0-based). Если индекс попал на согласную,
  ударение сдвигается к ближайшей гласной справа.
* `say_as` — принудительная замена для TTS.
* `confirmed: true` — вариант прослушан человеком. Копи подтверждённые: они
  переиспользуются во всех следующих роликах.

**Проверяй произношение до монтажа.** Переозвучка после сборки означает
пересчёт всех таймингов.

## Экранная форма ≠ произносимая

TTS произносит «сто пять», субтитр показывает «105». Связь хранится в токенах
(`src/lib/text.py`), P4 склеивает тайминги группы произнесённых слов обратно в
один экранный токен. Не ломай это, «упрощая» нормализацию.

Числительные разворачиваются в именительном падеже. Падеж и род по контексту не
выводятся — сложные числительные пиши в сценарии словами.

## Модель и фолбэк (R-4)

`eleven_v3` с фолбэком на `eleven_multilingual_v2`. Доступность v3 в API не
гарантирована, фолбэк срабатывает автоматически и пишет warning.
