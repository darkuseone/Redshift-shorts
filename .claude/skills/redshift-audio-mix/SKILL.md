# redshift-audio-mix

## Уровни (§4.4)

| Слой | Уровень |
|---|---|
| Голос | −14 LUFS, TP ≤ −1 dBTP |
| Музыкальная подложка | **−30…−34 LUFS** |
| SFX | пики −16…−12 dBFS |
| Финальный микс | −14 ±1 LUFS |
| Ducking | −6…−9 dB под речью |

Подложка должна быть **на грани слышимости**. Если музыка различима как мелодия
при обычном прослушивании — уровень завышен.

## Две ловушки, на которых легко ошибиться

**1. Порядок нормализации подложки.** Уровень задаётся **после** ducking и с
учётом гейна финального микса. Если нормализовать бед до этих операций, в
готовом файле он окажется на 5–7 дБ тише коридора, и QC-9 будет красным при
формально «правильном» коде.

**2. Моно в стерео.** BS.1770 суммирует мощность каналов: дорожка,
продублированная в оба канала, измеряется на **+3 LU громче**. Голос,
нормализованный в P3 как моно, надо привести к −14 LUFS ещё раз уже в стерео.

## SFX

Порядок поиска: локальная база по тегам. Нет нужной роли в библиотеке —
звук **не выдумывается**, пропуск фиксируется в `sfx_map.json`. Синтез в
библиотеку запрещён: короткие звуки кладёт заказчик.

Обязательные точки (§4.4.2): вход и выход аватара, появление full-screen text,
появление плашки, мем, финальный CTA. Плюс §4.3: каждый динамический переход
обязан сопровождаться SFX.

Плотность ≤ 1 раза в 2 сек. При конфликте приоритет у обязательных точек.

## Измерения — настоящие

`measure_loudness_file` использует ebur128 из ffmpeg. Параллельно есть
реализация BS.1770-4 на numpy для тестов — она сверена с ffmpeg, расхождение
0.08 LU. Не заменяй измерение на «примерно по пикам».
