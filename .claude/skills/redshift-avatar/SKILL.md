# redshift-avatar

`avatar_group_id`: `d0573be250724c23bed61037f1c7490d` — **группа** «Markus
Brown» (78 луков), это и есть «аватар 5» заказчика.
`avatar_id`: `af7c0cce1b0a4adea39c47f17815fef3` — лук из этой группы.

Разница не формальная: `get_avatar_look` по id группы отвечает 404, а создание
видео просит id **лука**. Положить группу в `avatar_id` — значит получить
`avatar_not_found` на первом же запросе.

`model_version` берётся из конфига — **не хардкодь**.

## Посегментная генерация (§7.4.1) — главная экономия

Генерируются только интервалы присутствия. При доле 44 % это экономит 56 %
кредитов относительно генерации всего ролика. Целевой показатель §1.3 —
не более 60 % длины ролика.

## Правило перебивок (§7.4.3, R-3)

Два аватар-сегмента подряд **без перебивки запрещены** — на стыке двух разных
генераций видно «прыжок» головы.

Точная формулировка правила (важно, здесь легко ошибиться):

* **разные блоки** → разные генерации → перебивка обязательна;
* **два сплита одного блока подряд** → перебивка **не нужна**: аватар там одно
  непрерывное видео, а меняется верхняя половина кадра — это само по себе
  визуальное событие;
* **два полнокадровых сегмента одного блока** → перебивка нужна, иначе склейка
  не меняет картинку вообще и ломает ритм §4.1.

Перебивка вырезается из **хвоста первого** сегмента.

## Липсинк (§7.4.4)

Строится по **финальной, уже обрезанной** озвучке: в провайдер уходит вырезанный
кусок `voice_final.wav`, а не текст. На таймлайн сегмент ложится кусками, и
QC-11 проверяет именно смещение выреза — там и разъедется липсинк, если
ошибиться.

## Кадрирование

Лицо обязано жить в полосе `y ∈ [350, 750]` (§3.5): ниже — и центральные
субтитры лягут на него. Если bbox лица опускается ниже `y = 800`, блок субтитров
смещается до `y = 1050`.

## Доля и появления

35–60 % хронометража, 2–5 появлений по 3–12 сек, первое — не позже 0:06.
Длинное непрерывное присутствие «приклеивает» аватара к кадру: появление длиннее
12 сек разбивается перебивкой.

## Альфа и фон: что HeyGen на самом деле отдаёт

Проверено измерением на боевых клипах, не по документации.

**Лук `af7c0cce…` (25.08): `outputFormat: webm` даёт настоящую альфу.**
Кадр ровно 1080×1920, 47 % полностью прозрачны, 46 % полностью непрозрачны,
край мягкий — волосы, дужки очков и штанга микрофона вырезаны чисто. Это и
есть рабочий режим: ключевание не нужно.

**Лук `54172d7a…` той же группы альфы не давал:** запрос принимался, приходил
VP9 в `yuv420p` с вшитым фоном и высотой 1936. То есть прозрачность — свойство
**лука**, а не аккаунта и не формата, и переносить вывод с одного лука на
другой нельзя.

### Расширение о прозрачности не говорит ничего

`.mov` и `.webm` раньше считались носителями альфы по имени файла. Именно так
непрозрачный webm ушёл в сборку как прозрачный: приёмы за головой встали за
непрозрачным планом, рендер потратил на них кадры, а в ролике их не было —
молча. Теперь альфа **измеряется**: `ffmpeg.has_alpha(clip)` достаёт
альфа-плоскость кадра и считает долю непрозрачных пикселей. Канал, залитый
единицами, альфой не считается.

Тонкость декодера: VP9 держит альфу отдельным блоком контейнера, и штатный
декодер ffmpeg отдаёт по такому файлу `yuv420p` — «альфы будто нет». Достаёт
её только `libvpx-vp9`, поэтому для webm декодер называется явно. На этом
легко ошибиться и второй раз объявить рабочую альфу отсутствующей.

### Голова меряется, а не берётся из полосы брендбука

Полоса `avatar.face_band_y` — догадка «голова обычно вот тут». На новом
аватаре она разъехалась с кадром: 475 px ширины против настоящих 354, центр
мимо на 39 px. Приёмы, которые ставятся относительно головы, вставали по
догадке, и слово за головой пришлось ей ровно поперёк — «НЕЧЕМ» читалось как
«НЕ⋯ЕМ».

С рабочей альфой догадка не нужна: `ffmpeg.head_box(clip)` читает силуэт. У
портрета профиль ширины непрозрачных строк всегда один: макушка (узко) →
череп (плато) → шея (провал) → плечи (резкий скачок вширь). Плечи ищутся по
наибольшему приросту ширины в верхней половине силуэта, подбородок — по самому
узкому месту между черепом и плечами. На боевом клипе вышло
`(402, 372, 756, 786)` — совпало с ручным промером профиля.

Без альфы остаётся полоса брендбука: догадка хуже измерения, но лучше, чем
ничего.

### Движение рук

`motionPrompt` работает у фото-аватаров на движке Avatar IV (на `avatar_v` он
требует анимационной ссылки — цифрового двойника в группе, которого у этой
группы нет). Вместе с `expressiveness: "high"` даёт жесты руками под речь.
Темп речи — `voiceSettings.speed`, у заказчика 1.1.

### Следствие для §5.3

Слово за головой требует матовой маски. Если клип пришёл без альфы, слово
окажется за непрозрачным видео — рендер потратит на него кадры, а в ролике его
не будет. Генератор композиции рисует `.behind-head` и подкладной фон только
для сегментов с `has_alpha`.

### Длительность

Клип возвращается на 4–40 мс длиннее заказанного (3.044 → 3.048 и 3.080).
Провайдер готовых клипов сверяет длительность с допуском 0.2 сек: этого хватает
на дрейф кодека и мало для реального рассинхрона.
