# redshift-asset-library

Принцип §14: **брендовые библиотеки конечны и стабильны, футажный кэш растёт.**
Одни и те же звуки и подложки во всех роликах — это не бедность, а узнаваемость
канала.

## Лимиты

| Библиотека | Лимит | Поведение при заполнении |
|---|---|---|
| `assets/sfx/` | 20 | курируемая: кладёт заказчик, `fill-libraries` не синтезирует |
| `assets/music/` | 15 | курируемая: кладёт заказчик через `add-music` |
| `assets/memes/` | 100 | заморожена, пополнение вручную заказчиком |
| кэш футажей | без лимита | LRU-вытеснение при переполнении storage |

Попытка добавить сверх лимита возвращает `LIBRARY_FROZEN`. Это **не баг**:
повторная генерация уже имеющегося звука — ошибка процесса (§4.4.4).

## Где что лежит (§14.5, конфликт K-12 переигран)

* SFX, музыка, мемы, шрифты, шаблоны — **в git-репозитории**: капнутые,
  стабильные, суммарно небольшие, версионируются вместе с кодом.
* Кэш футажей — **во внешнем storage** (local / S3 / R2); в репозитории только
  `cache/footage_index.json`.
* Выходные ролики — в артефактах прогона, не в репозитории.

Музыкальные подложки хранятся сжатыми (AAC 96k): 5 минутных WAV — это 67 МБ в
git, а на уровне −32 LUFS под речью разница неразличима.

## Формат записи (§14.6)

```json
{"id": "...", "type": "video|photo|sfx|music|meme|template", "source": "...",
 "license": "...", "url_origin": "...", "phash": "...", "tags": [...],
 "vision_summary": "...", "score": 0.86, "duration_sec": 4.2,
 "used_in": ["redshift_0014"], "last_used": "2026-08-18", "added": "2026-08-10"}
```

## Команды

```bash
python -m src.cli libraries                      # состояние и лимиты
python -m src.cli fill-libraries --kind memes    # долив мемов-заглушек; SFX и музыка руками
python -m src.cli maintenance --dry-run          # что вытеснит LRU
```

## LRU-вытеснение (R-11)

Вытесняется то, что дольше всех не использовалось. Материал из последних 5
роликов защищён: он ещё нужен для пересборки и участвует в QC-6.
