# redshift-cost-guard

## Две точки контроля (§7.6)

**До прогона** — смета по худшему сценарию (`estimate_cost`): озвучка всего
текста с запасом длины, аватар по верхней границе доли, vision по потолку пула,
генерация. Превышение лимита → `BUDGET_EXCEEDED` на P0, **до единого
потраченного кредита**.

**После каждого вызова** — журнал `CostLedger`. При
`budget.hard_stop_on_exceed: true` прогон останавливается на превышении, а не
«тихо» доедает бюджет.

## Где расход возникает

| Сервис | Драйвер | Как экономим |
|---|---|---|
| ElevenLabs | символы текста | одна корректирующая переозвучка максимум |
| HeyGen | секунды видео | посегментная генерация: 44 % вместо 100 % |
| Gemini | кадры | шаг 1 отсеивает 50–60 % **до** vision |
| Grok | кадры | лимит 8 вызовов, только спорные |
| Magnific | генерации | только незакрытые слоты, приоритет бесплатным моделям |

## Идемпотентность — тоже экономия

Повторный запуск с тем же входом **не тратит кредиты повторно**: шаг сверяет
хеш входа с кэшем. Оценка материала из локальной базы переиспользуется.

## Mock-режим

При `providers.mode: mock` расход пишется в журнал с флагом `mock: true` и
нулевой стоимостью. Так видно структуру расхода без трат — удобно для проверки
сметы перед боевым прогоном.

```bash
python -m src.cli --set providers.mode=mock run --script scripts/x.json
cat output/<id>/cost_report.json
```
