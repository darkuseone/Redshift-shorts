# redshift-learning

## Запись выбора A/B (§4.5)

```bash
python -m src.cli learn --video-id redshift_0042 --choice A --note "хук читается лучше"
```

Записывается **не ярлык версии**, а ситуация: «в ситуации X выбран вариант Y».
Ситуация — это конкретное монтажное решение, которым версии различались:
`kenburns@twist`, `transition@setup`, `fullscreen_text@develop`,
`asset_order@b3`, `overlay@plaque`.

Именно эти решения смещают дефолты. Записывать «нравится B» бесполезно: в
следующем ролике версии B не существует.

## Как смещаются дефолты

Выбранный вариант получает +1.0, отвергнутый −0.5. При накоплении веса ≥2.0
вариант становится дефолтом для своей ситуации. Со временем разброс между A и B
сужается, и канал переходит на одну версию — это и есть цель §4.5.

## Что обновляется после каждого прогона (§7.8)

| Файл | Что записывается |
|---|---|
| `config/editing_preferences.json` | выбор A/B и чем версии различались |
| `config/pronunciation.json` | подтверждённые ударения |
| `templates/manifest.json` | использование шаблонов (основа ротации) |
| `cache/footage_index.json` | новые материалы, `used_in`, `last_used` |
| `instruction.md` | согласованные изменения правил |
| `rejected_patterns.md` | что пробовали и не берём |

## Правило про instruction.md

Любое согласованное в диалоге изменение правил отражается в `instruction.md`
**в тот же прогон**. Инструкция — исполняемый документ, а не летопись: если
правило живёт только в переписке, следующий прогон о нём не узнает.

В разделе «История изменений» пиши **причину**, а не только факт. «Перебивка
ставится только между разными генерациями» без объяснения «внутри блока аватар
непрерывен» через месяц выглядит произволом и будет откачено обратно.
