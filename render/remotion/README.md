# Remotion — альтернативный движок рендера

Читает тот же `edit_plan_*.json`, что и встроенный композитор на ffmpeg.
Переключение — в `config/config.yaml`:

```yaml
render:
  engine: ffmpeg    # ffmpeg | remotion
```

## Статус

**Движок по умолчанию — `ffmpeg`**, и он проверен: собирает обе версии ролика,
проходит все 19 блокирующих проверок §11.1, работает на CPU-раннере без Node и
без headless-браузера.

Этот проект — типизированный слой, повторяющий ту же композицию на Remotion.
Он собран и оттипизирован, но **сквозной рендер через него не проверялся**:
для этого нужны установленный Node-стек и headless Chromium, которых нет в
CPU-раннере GitHub Actions по умолчанию (§10.5.1). Прежде чем переключать
`render.engine`, прогоните `npm install && npm run typecheck && npm run render`
на целевой машине и сверьте результат с ffmpeg-сборкой покадрово.

## Запуск

```bash
npm install
npm run typecheck
npx remotion studio src/index.tsx                       # предпросмотр
npx remotion render src/index.tsx Redshift out/A.mp4 \
  --props=../../output/redshift_0042/edit_plan_A.json
```

Шрифты подключаются из `assets/fonts/` — те же проверенные гарнитуры
(Oswald, Nunito, JetBrains Mono), что и в основном движке. Гарнитуру без
кириллицы подключать нельзя: см. скилл `redshift-fonts`.

## Соответствие движков

Оба движка обязаны давать одинаковый монтаж: одни и те же слоты, тайминги,
шаблоны и тексты приходят из edit-плана. Расхождение допустимо только в
микро-деталях растеризации (сглаживание шрифта, интерполяция при масштабе).
Всё, что крупнее, — баг одного из движков.
