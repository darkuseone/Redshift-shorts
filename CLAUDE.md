# REDSHIFT — как работать с этим репозиторием

## Железные правила агента

1. Live run только в Actions по заявке `config/ci_build_request.json` (или ручной `workflow_dispatch` заказчика). Не коммитить заявку «на всякий» с фиксом багов.
2. Cursor не вызывает `src.cli run` в live. Mock (`providers.mode=mock`) — только тесты и сухой прогон.
3. Ключи не печатать. Секреты живут в GitHub Actions secrets.
4. Аватар только MCP → `assets/avatar_clips/<id>/` (лук `99ccc74e764947c394cd4ef210960a6f`, engine `avatar_v`, webm+alpha) → `heygen.source=prepared`. Live HeyGen API из чата не звать.
5. Нет новой озвучки и нового аватара на фикс QC. Перерендер `--from P7` (или `--from P11`, если менялись только композитор/сабы/SFX). Смена текста блоков = новый `video_id`.
6. Одна версия монтажа. Не A и B.
7. Аватар ≤5 появлений и ≤50 % длительности ролика.
8. Vision = Grok (grok-4.6), не GLM. Gemini — только если Grok недоступен. `providers.allow_xai` для image gen не размораживать без нужды.
9. Не читать файлы >40 КБ целиком (правило ниже).
10. Не пушить mp4. Выход живой сборки — artifact Actions и/или S3.
11. Триггер станка = только `config/ci_build_request.json` (токен агента не умеет `workflow_dispatch`). `ci.yml` на feature-ветках не бежит.
12. QC-пакет: много кадров + звук (хук/середина/финал). Релиз ≥9/10 по всем осям `config/qc_agent_rubric.json`. Чеклист не вечный канон, пока серия не держит 9/10.

Полный контракт Cursor↔Actions — в [`instruction.md`](instruction.md) §0.

## Правило чтения: ни один файл больше 40 КБ не читается целиком

Три файла проекта переросли размер, на котором чтение целиком перестаёт быть
работой и становится тратой контекста:

| файл | размер | зачем в него лезут | как читать |
|---|---|---|---|
| `src/lib/render/hyperframes/templates.py` | ~700 КБ | найти один рендерер | `grep -n "def r_<name>"`, затем `sed -n 'X,Yp'` |
| `templates/manifest.json` | сотни КБ | узнать категорию и требования приёма | `templates/manifest.index.json` |
| `config/template_scenarios.json` | сотни КБ | понять, какой интент ведёт в категорию | `config/template_scenarios.index.json` |

Индексы отвечают на три вопроса без открытия источника: какие есть категории
и сколько в них приёмов, какой у приёма рендерер и требования, какие интенты
ведут в эту категорию. Дальше — точечный `grep -n` и срез по строкам.

Индексы **производные**. Меняется источник — перегенерировать:

```
python tools/gen_indexes.py            # переписать
python tools/gen_indexes.py --check    # проверить совпадение (код 1, если разошлись)
```

Проверка стоит в тестах, поэтому устаревший индекс не проживёт незамеченным.

## Прогон тестов

```
python -m pytest -q --ignore=tests/test_music_library.py
```

`tests/test_music_library.py` исключается намеренно: он ходит в сеть и висит,
когда она недоступна. Это поведение существовало до текущей волны — проверено
на чистом HEAD.

## Деньги

Полный прогон тратит кредиты ElevenLabs и HeyGen — это всегда решение
заказчика, а не агента. Пересборка из кэша (`--from P7`, `heygen.source=prepared`)
не трогает ни голос, ни аватар. Даже `--force` не снимает запрет; только явный
`--force-paid`, которого в заявке Cursor быть не должно.

Секреты живут только в GitHub Actions secrets, в логах редактируются и в
артефакты не попадают. Не выводить их в консоль ни при каких обстоятельствах.
