# REDSHIFT — мастер-инструкция сборки

**Версия:** 1.0 · **Основание:** ТЗ v2.0 · **Статус:** исполняемый документ

Все ролики собираются **по этой инструкции**, а не по памяти диалога (§10.1).
Любое согласованное изменение правил отражается здесь **в тот же прогон** (§7.8).

## 2. Порядок пайплайна

```
P0  Валидация сценария и конфига      → validated_script.json
P1  Планирование режимов кадра        → draft_plan.json
P2  TTS с запасом длины +18…25 %      → voice_raw.wav, tts_meta.json
P3  Оптимизация речи                  → voice_final.wav, speech_map.json
P4  Word-level выравнивание           → words.json, subtitles.srt
P5  Монтажный план (слоты)            → cut_plan.json
P6  Аватар посегментно                → avatar/seg_*.mp4, avatar_meta.json
P7  Поиск B-roll                      → candidates.json
P8  Трёхступенчатая оценка            → accepted_assets.json
P9  Генерация пустых слотов           → generated_assets.json
P10 SFX + подложка + микс             → sfx_map.json, music_bed.wav, mix.wav
P11 Сборка edit-планов A и B          → edit_plan_A.json, edit_plan_B.json
P12 Рендер, QC, артефакты             → *.mp4, build_report.json, cost_report.json
```

Каждый шаг идемпотентен и кэшируется по хешу входа. Падение на шаге N не требует
перезапуска с P0:

```bash
python -m src.cli run --script scripts/redshift_0042.json --from P7
python -m src.cli run --script scripts/redshift_0042.json --only P11 P12 --force
```

## 3. Правила выбора режимов кадра

| Роль блока | Режим по умолчанию | Комментарий |
|---|---|---|
| `hook` | C (или A) | сильный футаж либо full-screen text |
| `setup` | A | первый вход аватара, не позже 0:06 |
| `evidence` | B | сверху доказательство, снизу аватар |
| `develop` | C с врезками A | цифры, графика, Ken Burns |
| `twist` | A | hero-кадр, акцентное слово |
| `cta` | A или C | кнопка подписки в последние 2 сек |

Ограничения: режим B ≤25 % хронометража, непрерывный блок футажа ≤40 %,
появление аватара 3–12 сек, появлений 2–7.

Директивы `avatar: on|off` из сценария неприкосновенны. Если из-за них аватар не
успевает появиться до 0:06, P1 возвращает конфликт `AVATAR_FIRST_APPEARANCE_LATE`
— это сигнал сценаристу, а не повод нарушить §6.

## 3.1 Приёмы и шаблоны: по смыслу, а не по списку

**Каталог — не чек-лист.** Ни один ролик не обязан показать все приёмы. Шаблон
ставится там, где он что-то значит, и больше нигде. Узнаваемость канала держит
**один** брендбук, разнообразие — **много** шаблонов, из которых каждый ролик
берёт горстку. Чем больше каталог, тем реже приём повторяется от ролика к
ролику: это цель, а не побочный эффект.

Отсюда три следствия.

**Какой приём — решает содержимое кадра, а не счётчик.** `_HERO_NEEDS` не
формальность: нечем наполнить приём — приёма нет. Окно переписки появляется
там, где в реплике вопрос; окно генерации — где речь о генерации; карточка
источника — где источник есть. Счётчик решает только «как часто» (каждый
второй аватар-кадр); если и это начнёт читаться механически, ослаблять надо
счётчик, а не содержательный отбор.

**Долгий план ведущего — законный монтажный ход, а не дыра.** Говорящая голова
может стоять три-пять секунд, если момент того стоит. Ограничение §1.4 (план
≤5 сек, 7 с внутренними событиями) — потолок, а не цель. Закрывать паузу
приёмом «чтобы не было пусто» запрещено: это ровно тот случай, когда графика
работает против ролика.

**Динамика при этом обязана остаться.** §1.3 — визуальное событие не реже
1 раза в 2.5 сек — никуда не делось, но событием считается и движение **внутри**
плана: наезд, дрейф, слово субтитра, звуковой акцент. Смена кадра — не
единственный способ его выполнить.

**Как база растёт.** Заказчик присылает отрывок ролика, который ему понравился,
— из отрывка делается шаблон и кладётся в каталог по порядку «Как добавить
приём по скриншоту» (скилл `redshift-templates`). База пополняется постоянно и
намеренно: это и есть механизм, которым ролики перестают походить друг на друга.

## 4. Правила текста и графики

**Субтитры.** Одно слово, по центру кадра, baseline 940–1010 (в режиме A
опускается до 1050, если лицо ниже y = 800). **Montserrat Black, прописными,
белое** — начертание с эталонного кадра заказчика. Длительность слова
250–450 мс, pop-in 90–120 мс.

Читаемость держит **красное гало**, а не чёрная тень и не обводка. Оно из двух
частей, и обе нужны: узкий ободок в 2 px почти непрозрачного `accent` — это край
буквы, на светлом грунте слово держится только им; и широкое размытое зарево
(8 → 90 px, `accent` → `accent_deep`, гаснущее к краям) — оно сажает слово в кадр.
Чёрного в субтитре нет нигде.

Поверх этого прод кладёт жест `gradient-fill`: bounce и кровавый градиент
`accent → accent_soft` на одном акцентном слове. Если тема космоса —
`clip-wipe` (маска слева направо, акцент `#C8453D` вместо жёлтого каталога).
`blend-difference` — только явным `caption`: белые слова инвертируются
о футаж (`mix-blend-mode: difference`, не твин), акцент остаётся кровью.
Pop-in Nunito больше не собирается.

Акцентное слово — та же наклейка наизнанку: заливка `accent_soft`, ободок
светлый на тёмной сцене и `accent_deep` на светлой (белый над стеной студии
пропадает вместе с фоном).

Слово в один-два знака отдельной репликой не показывается: оно приклеивается к
следующему («а расчёты», «не в бюджет»). Такая реплика живёт 60–130 мс —
прочитать её нельзя, а мелькание одной буквы посреди кадра читается как сбой
рендера. Акцент при этом остаётся на знаменательном слове: приклеенное начало
рисуется своим цветом, иначе красный означал бы «начало фразы», а не ударение.

**Full-screen text.** 2–4 раза за ролик, 0.8–2 сек, кегль 200–420 px, 1–4 слова,
всегда с SFX. Красным выделяется одно слово, не строка: акцент, совпавший со
всей фразой, не ставится вовсе — фраза из одного слова выделена размером. Под
фразой всегда что-то есть: материал кадра, а если его не нашлось — сцена фона
ролика. Пустая заливка запрещена.

**Плашки.** Радиус 24 px, фон `bg_light` 92 %, рамка 2 px `accent` 40 %. Выезд
200–280 мс с overshoot 6–8 %, уход в ту же сторону 160–200 мс.

**Подсветка.** Затемнение 78 %, вырез вокруг цели, удержание 0.6–1.2 сек,
1–3 раза за ролик. Обязательна при показе скриншота статьи.

**Источник.** Карточка шириной во всю рабочую зону (68 % кадра — выше минимума
60 % из §5.6), домен и заголовок читаемы.

**Цвет.** Акцент ≤10–12 % площади кадра. Фон под аватаром светлый и спокойный:
заливка акцентом съедает весь лимит.

## 5. Правила отбора футажей

0. **В базе — только настоящий материал.** Синтетика мок-режима в общий индекс
   не пишется: он просматривается раньше внешних стоков, и запись без файла
   стоит слота, ушедшего в генерацию.
0. **Генерация — последняя очередь и не бесплатный пропуск.** Сгенерированный
   кадр проходит того же vision-судью, что и сток: ниже порога отбраковки он не
   идёт в монтаж. Не вышло за три попытки — слот остаётся пустым. Пустой слот
   видно в отчёте, слабую генерацию — только зрителю.
1. **Сначала локальная база.** Оценённый материал не покупается повторно. Она
   лежит в репозитории (`assets/footage`, потолок 400 МиБ, дальше LRU): раннер
   прогон не переживает, а checkout переживает всё.
2. Запросы **на английском из смысла блока**, 3–5 формулировок разной
   абстракции. Русский текст не переводится подстрочно.
3. Приоритет источников — по типу запроса (`config/stock_sources.yaml`).
4. Лицензия проверяется **до** скачивания. Internet Archive — попозиционно.
5. Скачиваний ≤50 на ролик. Бюджет делится между слотами по-честному:
   метаданные собираются бесплатно по всем запросам, затем кандидаты
   ранжируются (вертикаль → запас длительности → приоритет источника).
6. Дедуп pHash внутри ролика и против всей базы, порог 8/64.
7. Оценка в три шага: дешёвая отбраковка → Gemini по 3 кадрам → арбитраж Grok
   только на спорных (score 0.45–0.70, расхождение кадров > 0.3, роли
   `evidence`/`twist`), лимит 8 вызовов.
8. Незакрытый слот идёт в **генерацию**, а не заполняется слабым футажом.
9. Доля AI-футажа ≤40 %; генерация останавливается, когда следующий слот вывел
   бы за потолок.

## 6. Правила звука

| Слой | Уровень | Проверка |
|---|---|---|
| Голос | −14 LUFS, TP ≤ −1 dBTP | P3, QC-8 |
| Подложка | −30…−34 LUFS **в готовом миксе** | P10, QC-9 |
| SFX | пики −16…−12 dBFS, плотность ≤1 / 2 сек | P10 |
| Финальный микс | −14 ±1 LUFS | P10, QC-8 |

Подложка нормализуется **после** ducking и с учётом финального гейна микса —
иначе в готовом файле она окажется на 5–7 дБ тише коридора.

Моно-дорожка, продублированная в стерео, измеряется на +3 LU громче: голосовой
слой приводится к −14 LUFS уже в стерео.

SFX берутся **только** из библиотеки. Нет роли в библиотеке — звук не
выдумывается, пропуск фиксируется в отчёте.

## 7. Чек-лист QC (19 блокирующих проверок)

Полный список — в `src/p12_render_qc/qc.py`, нумерация совпадает с §11.1.
Провал любой блокирующей проверки означает: ролик **не выдаётся**, файл
переносится в `output/<id>/rejected/`, причина и таймкод пишутся в
`build_report.json`.

Смысловой QC (§11.2) — vision по финальному ролику: соответствие картинки
произносимому, читаемость текста, артефакты. Включается `features.vision_qc`.
